How NearStock works

A smart nearby-inventory discovery system: shops push stock from their billing counter, customers search for a product and get every nearby shop that has it, ranked by real distance.

The flow

  Shop billing / POS system
            │  stock delta (product sold or restocked)
            ▼
  Node.js + Express REST API
            │  read / write
            ▼
       MySQL  ──────────────  (seeded in-memory store when no DB is configured)
            │
            ▼
  Customer app (this website · same API a Flutter client would call)
            │
            ├─ search for a product      → linear search + merge sort
            ├─ find shops that stock it  → inventory join
            ├─ calculate distance        → Haversine formula
            ├─ rank shops                → MinHeap, k-smallest extraction
            └─ place a request           → Queue, enqueue O(1)
                                            shop serves front → dequeue O(1)

Data structures

Queue — the primary structure

Customer requests are held in a First-In-First-Out queue, one per shop, so a shop always serves whoever has waited longest. It is implemented in server/lib/queue.js as a circular array (ring buffer) rather than a plain JavaScript array, because Array.shift() is O(n) — it re-indexes every remaining element. A ring buffer keeps a front and a rear index and wraps them with modulo, so: 

  front ─┐                        ┌─ rear
         ▼                        ▼
  [  _ ,  R1 ,  R2 ,  R3 ,  _ ,  _ ,  _ ,  _  ]
          ▲ dequeue here    enqueue here ▲

  enqueue(x)   O(1)      isEmpty()   O(1)
  dequeue()    O(1)      size        O(1)
  peek()       O(1)      remove(p)   O(n)   (cancellation)

When the ring fills, the backing array doubles and is re-linearised — amortised O(1) per insertion. Against MySQL the same ordering is enforced by a monotonically increasing position ticket column: dequeue is the smallest position still 'waiting'.

MinHeap — finding the nearest shop

Once every stocking shop has a distance, "which is nearest?" is a minimum-extraction problem. server/lib/minheap.js builds a binary min-heap with Floyd's bottom-up heapify in O(n) and extracts the k closest shops in O(k log n) — cheaper than a full O(n log n) sort whenever k is small, which it always is (a customer wants the top 3–5). Ties break toward in-stock first, then lower price.

Searching and sorting

Product lookup is a linear scan scored so prefix matches outrank mid-string ones, with a binary search over a name-sorted index as an exact-match fast path. Ranking uses a hand-written stable merge sort rather than Array.prototype.sort, so the divide-and-conquer step stays visible in the codebase.

Distance

The Haversine formula gives the great-circle distance between two latitude/longitude points on a sphere of radius 6371 km. It is available both in JavaScript (server/lib/geo.js) and as the MySQL stored function haversine_km() in db/schema.sql, so ranking can be pushed down into SQL when the catalogue grows.

Database

  users          user_id, name, email, phone, role, latitude, longitude
  stores         store_id, owner_id → users, name, category, address,
                 city, phone, latitude, longitude, opens_at, closes_at, rating
  products       product_id, name, brand, category, unit, base_price, barcode
  inventory      inventory_id, store_id → stores, product_id → products,
                 quantity, price, updated_at        UNIQUE(store_id, product_id)
  request_queue  request_id, store_id, product_id, customer_name, quantity,
                 position, status, enqueued_at, processed_at
  billing_sync   sync_id, store_id, product_id, delta, source, synced_at

v_availability joins inventory to products and stores for the search path, and idx_queue_fifo (store_id, status, position) makes the dequeue lookup an index seek.

Running it with MySQL

The app runs on a seeded in-memory dataset out of the box. To switch to real MySQL:

  mysql -u root -p < db/schema.sql
  mysql -u root -p nearstock < db/seed.sql

  # then set either
  DATABASE_URL=mysql://user:pass@host:3306/nearstock
  # or
  DB_HOST=localhost  DB_USER=root  DB_PASSWORD=secret  DB_NAME=nearstock

The data layer detects the connection at boot and switches drivers; the routes never change. If MySQL is configured but unreachable the app logs the reason and degrades to the in-memory dataset rather than failing the whole site.

Building a Flutter client

Every screen on this website is a plain fetch against the REST API, so a Flutter app is a drop-in second client: call GET /api/search?q=milk&lat=..&lng=.. with package:http, take the device position from geolocator, and POST /api/queue to join a shop's line.
